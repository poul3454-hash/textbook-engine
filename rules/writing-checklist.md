# 집필·피드백 절차 체크리스트

내용 기준(저자 성향·커버리지·난이도)의 원본은 프로젝트 문서 `저자-집필성향-프로파일.md`, `제작-결정-로그.md`다. 여기는 엔진과 함께 돌리는 절차만.

## A. 새 강 집필
0. 커버리지: 참고서 해당 단원의 **주제 목록만** 인벤토리로 추출 (원문 미전사). 설명·문제는 백지에서 자작, 전 문항 sympy 검산
1. 서술 골격은 저자 키워드 메모를 먼저 받는다 (연속편부터의 방식). 골격 없이 쓴 초안은 "초안"으로 표시
2. 순서: 질문 한 줄 → 안 되는 예시 그림 → 개념(증명 없음) → 관점 → 예시 → 오진 주의 → 문진 → 필수예제 2 → 유제 2 → STEP
3. 문장: 단문, 줄표 없음, **비유·의인화·수사 없음(저자가 준 것만 유지)**, 교과서 표준 동사('x축과 만난다', '점을 지난다', '존재하지 않는다'), 수능 언급 없음
4. 개념·반례마다 그림, 예시는 자체완결
5. 정석/직관 병기, 초진은 꼴 식별까지만
6. 빌드 → `scripts/check.py` (고아 0·파리티·백지·정답 푸터) → `scripts/stylescan.sh` → `scripts/contact_sheet.py`로 레이아웃 확인
7. 집필 노트에 구성·정답·저자 확인사항 기록

## B. 저자 빨간펜 반영 사이클
1. 스캔 PDF → `scripts/redpen_scan.py` 로 **전 쪽 빨간 픽셀 스캔** → 표시 있는 쪽의 띠 크롭을 위에서부터 하나씩 판독 (콘택트시트만 보고 판독하지 않는다)
2. 판독 문서: 항목마다 `쪽·위치 / 리뷰 원문 / 처리 / 소스 위치`. 취소선 범위가 애매하면 되묻는다 (임의로 넓히지 않음). 한 글자 오독 주의 ('꼴을' vs '조건을')
3. 사용자가 "수정해"라고 할 때까지 소스 수정 금지. 누락분도 대기 목록에만
4. 반영: 백업 → python 치환(`assert old in s`) → 빌드 → check → 바뀐 쪽 렌더 확인 → 전달
5. 저자가 방향을 바꾼 뒤 모순되게 남은 **내 문장**(초안의 라벨·헤더·출제 차트)은 표시가 없어도 내가 맞춘다. 되물을 것은 저자 문장·교수법 선택뿐
6. 반영 뒤 사용자 정독 2차 검수가 있다. "반영됐다"는 렌더링을 본 뒤에만

## C. 전달
- `<책> <편> N-M강 vX.Y.pdf` 로 샘플 폴더 저장 (덮어쓰기 금지)
- 프로젝트: 조판 소스(편별 최신판 1개), 판독 문서, 집필 노트, 결정 로그 갱신
